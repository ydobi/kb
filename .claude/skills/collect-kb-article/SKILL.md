# 收录文章到知识库

将链接内容收纳到 `docs/` 知识库，自动分类并创建文档。

## 触发方式

用户可能直接给出 URL，或沿用习惯写法：`/collect <链接URL>`。以 URL 与意图为准。

## 执行步骤

### 1. 获取内容

使用可用的网页抓取能力（如 WebFetch / 浏览器 MCP）获取用户提供的链接内容，提取：

- 标题
- 作者（若有）
- 正文完整内容（保留技术细节、代码与配置示例）

### 2. 分析分类

根据内容主题判断应放入哪个分类：

**AI Coding 相关**：

- `ai-editors` — AI 编辑器/IDE（Cursor、Copilot、Claude Code 等）
- `prompt-skills` — Prompt 技巧
- `ai-workflow` — AI 辅助工作流
- `ai-frameworks` — AI 开发框架

**前端开发相关**：

- `frameworks` — 框架（React、Vue 等）
- `languages` — 语言基础（TypeScript、JavaScript、CSS）
- `build-tools` — 构建工具（Vite、Webpack）
- `engineering` — 工程化实践

**工具相关**：

- `editors` — 编辑器（VS Code 等）
- `debugging` — 调试工具
- `version-control` — 版本控制（Git）
- `productivity` — 效率提升

**其他**：

- `best-practices` — 最佳实践

路径需与现有 `docs/` 目录结构一致（如 `docs/ai-coding/ai-frameworks/`）。

### 3. 确认分类

在创建文件前请用户确认：

- 分类是否合适
- 若多个分类都合理，请用户选择

若无法使用结构化提问工具，在对话中简要列出选项并请用户回复即可。

### 4. 创建文档（初稿）

- 文件名使用中文（如 `渐进式AI编码框架.md`）
- 文首添加来源：`> 来源：[链接标题](链接URL)`；若有作者可加一行引用
- 保留原文完整信息，不删减技术内容
- 先将抓取结果落为可编辑的 Markdown 初稿（允许结构尚乱）

### 5. 格式检查与调整

在定稿前对初稿做一次**通读整理**（不删改技术含义与原文论据）：

**结构**

- 全文**仅一个**一级标题（`#`），与页面标题一致；正文大节用 `##`，小节用 `###` / `####`，层级连续、不跳级
- 中文章节号（如「一、」「1.1」）与抓取段落对齐为对应层级标题，避免大段「无标题正文墙」

**表格与列表**

- 抓取/HTML 转文本常把表格打成「每格一行」：合并为合法 Markdown 表格（表头 + 分隔行 + 行）
- 并列要点、铁律、步骤改为有序或无序列表；编号段落保持语义顺序

**代码与围栏**

- 代码块标注语言（如 `text`、`bash`、`markdown`、`java`）；目录树、ASCII 示意优先用 `text` 围栏
- **禁止**在以 markdown 为语言的围栏代码块内再嵌套一层三个反引号围栏（会提前闭合外层）；内层改用**缩进代码块**（行首四个空格）或并入 `text` 单段
- 对话/日志类长引用可保留在单个 `text` 代码块中，或仅在可读性明显提升时拆段

**链接与噪音**

- 「参考」等外链列表改为 `[标题](URL)` 形式
- 删除平台无关尾噪：如「阅读原文」「Scan to Follow」「环境异常去验证」等按钮文案

**VitePress 友好**

- 正文中少用裸 `<Tag>`，Angle bracket 参数可写成中文括号、行内代码或全角括号，避免被当成 HTML
- 引号、书名号以中文排版习惯为主，与知识库其他文档一致即可

### 6. 更新配置

更新 `docs/.vitepress/config.mts` 中对应 `sidebar` 分组，加入新文档的 `text` 与 `link`（与 VitePress 现有 `base: '/kb/'` 下的路径约定一致）。

### 7. 提交变更（用户未拒绝时）

```bash
git add .
git commit -m "docs: 收录文章 <文章标题>"
```

仅当用户希望一并提交时执行；否则止于文件与配置修改。

## 知识库根目录

本项目内相对路径：`docs/`（勿写死本机绝对路径）。

## 注意事项

- 链接无法抓取时（如部分微信文章）：请用户粘贴正文或导出内容
- 保持原文完整性，不删减技术细节；**格式调整不等于删内容**
- 文档标题与文件名与内容一致、便于检索
- 若用户明确要求「只收录不排版」，可跳过 §5 中的部分结构调整，但仍建议去除尾噪、修复明显坏链的围栏
