# GSD 多 Agent 上下文工程框架

开源约 5 天即获得约 5 万 Star，在 GitHub 历史上也属于较高热度。最近在 X、小红书等平台常能刷到一个叫 **GSD（Get Shit Done）** 的开源项目；评论区有人称它为 Claude Code 的「灵魂伴侣」，也有人称它为 Vibe Coding 的终结者。

- 开源仓库：[gsd-build/get-shit-done](https://github.com/gsd-build/get-shit-done)

## GSD 是什么

一句话：**GSD 是一个上下文工程框架**，让 AI 在处理长程、复杂任务时尽量保持高质量、稳定的输出。

它针对的现象很具体：不论写代码、调研、搭产品还是做方案，只要任务拉长、对话变多，模型输出质量往往会明显下降——回答变短、需求遗漏、逻辑变乱。这种现象常被称为**上下文腐烂（Context Rot）**。

与「在单一会话里一直聊下去」不同，GSD 把大任务拆成多个小任务，**每个小任务由独立 Agent 在相对干净的上下文里执行**；中间有研究员做调研、规划师拆任务、执行者落地、验证者检查，**主对话窗口尽量只负责协调**，避免被历史信息塞满。

文中提到该项目在 GitHub 上曾达到约 49,200+ Star、全球排名约 407；作者为独立开发者。（具体数字随时间变化，以仓库页面为准。）

## 核心特性

### 缓解上下文腐烂

传统用法里，多轮对话后上下文窗口接近上限时，输出质量容易下滑。GSD 的思路是：**子任务在独立的较大上下文（文中举例为约 200k token）中执行**，主协调窗口尽量维持在较低占用（文中称约 30%–40%），让执行侧尽量在「较干净」的窗口里工作。

### 多 Agent 并行协作

任务拆分后交给不同角色的 Agent（文中描述）：

- **研究员**：调研技术方案与领域知识  
- **规划师**：把任务拆成可执行的原子计划  
- **执行者**：在独立上下文里写代码、落地  
- **验证者**：检查交付是否达标  

独立且无强依赖的任务可并行；GSD 用 **Wave** 组织任务：**同一 Wave 内并行**，有依赖的排到后续 Wave。

### 结构化的任务指令

执行计划采用 **XML 结构**，细化到文件路径、步骤、验证方式、完成条件等，减少「模型猜需求」带来的偏差。

示例如下（语义与原文一致，排版已整理）：

```xml
<task type="auto">
  <name>创建登录接口</name>
  <files>src/app/api/auth/login/route.ts</files>
  <action>
    用 jose 库做 JWT（别用 jsonwebtoken，有 CommonJS 兼容问题）。
    验证用户凭据。
    成功后返回 httpOnly cookie。
  </action>
  <verify>curl 请求登录接口返回 200 + Set-Cookie</verify>
  <done>有效凭据返回 cookie，无效凭据返回 401</done>
</task>
```

### 状态追踪与断点续作

GSD 会维护一套项目状态相关产出（如愿景、需求、路线图、决策、阻塞项、已完成工作等），**跨会话持久化**，便于隔天接续。文中提到命令：

- `/gsd-pause-work`：生成交接文档  
- `/gsd-resume-work`：恢复接续  

### 安装与工具覆盖

除 Claude Code 外，文中称还支持 OpenCode、Gemini CLI 等多种 AI 编码工具；安装流程为交互式（选择工具、全局或项目内安装等）。

## 完整工作流

以下按原文顺序整理（从零搭产品类场景）。

### 第一步：初始化项目

命令：`/gsd-new-project`

会先澄清目标、约束、技术偏好等；再派研究员做领域调研，将需求分为 v1、v2、暂不考虑等，并生成路线图。确认路线图后可进入执行。

### 第二步：讨论细节

命令：`/gsd-discuss-phase 1`

把各阶段一句话级别的路线图展开为具体偏好（布局、接口形态、错误处理等），整理为 **CONTEXT** 文档，供后续研究与规划引用。

### 第三步：规划阶段

命令：`/gsd-plan-phase 1`

系统派研究员调研实现方案，规划师生成若干原子任务计划（XML 结构）；另有检查员验证计划是否覆盖需求，不通过则退回重做。

### 第四步：执行阶段

命令：`/gsd-execute-phase 1`

计划按依赖分 Wave，同 Wave 并行执行；每个任务在独立大上下文中运行，任务完成可对应产生 Git commit（文中描述）。

### 第五步：验收成果

命令：`/gsd-verify-work 1`

逐项确认可交付物；有问题则派调试类 Agent 查因、生成修复计划，再执行 `/gsd-execute-phase` 修复。

### 快捷方式

- `/gsd-quick`：适合不需要完整流程的临时任务  
- `/gsd-next`：由系统判断当前应执行的步骤  

## 不只是写代码

核心能力（上下文管理、多 Agent 协作、结构化拆解）同样适用于**需要 AI 长时间、高质量完成的复杂非编码任务**，例如深度行业调研、从零到一的产品方案（市场分析、技术选型、架构与实施计划等）。

文中提到：作者在 README 中自述为独立开发者，由 Claude Code 承担编码；GSD 用于驱动该工作流；并有来自 Amazon、Google、Shopify、Webflow 等公司的工程师使用（为文中转述，不代表官方背书）。

## 怎么上手

安装（文中命令）：

```bash
npx get-shit-done-cc@latest
```

若使用 Claude Code，文中建议可配合：

```bash
claude --dangerously-skip-permissions
```

说明：GSD 侧重自动化执行，跳过权限检查可减少频繁确认；**需自行评估安全风险**。

安装后在 Claude Code 中可使用 `/gsd-help` 查看命令列表。

若已有进行中的项目，可先 `/gsd-map-codebase` 扫描代码库，再 `/gsd-new-project` 初始化。
